# Navigation and cancellation follow-up — 2026-10-09

This follow-up retains the lean Bash normal/roulette loop and existing MCP
input backend. It adds no background service, polling, configuration option or
SD-card activity during gameplay.

## Confirmed navigation defect

The loading-input drain handled Next but discarded Previous. It now retains
one pending Next/Previous action, with the last navigation key in a burst taking
precedence. Previous survives the post-launch transition and replays the prior
record on the next iteration. It does not build a queue of repeated presses.

Both new deterministic tests fail against the preceding lean runtime and pass
against this revision. These establish the loading-phase bug; they do not prove
the cause of the historical missed Previous reported while controls appeared
ready.

## Stop timing investigation

Initial public CLI stops took 3.17 seconds from PSX and 2.75 seconds from SMS.
Instrumented stops immediately after starting SNES took 6.08 and 7.59 seconds.
These are different workloads, not controlled before/after comparisons.

The detailed trace measured preparation cancellation at 1.32–1.39 seconds.
The fallback process-tree walk scanned `/proc` again for every descendant on
this MiSTer kernel, which lacks the per-process children interface.

Other observations: sourcing the backend took 0.55–0.81 seconds under these
loads; ordinary cleanup and OLED teardown returned quickly. Menu load writes
returned in approximately 0.05 seconds, while confirming Menu during an ongoing
SNES transition took several seconds. The asynchronous OLED timeout was not on
that critical path. Volume bindings remained present until Menu was observed.

The patch targets process-tree cancellation rather than weakening Menu/audio or
ownership checks. Hardware transition time remains part of total Menu latency.

## Darkstalkers reproduction

Installed `/media/fat/_Arcade/Darkstalkers The Night Warriors (Europe 940705).mra`
uses Jotego CPS2 (`jtcps2`, set `dstlk`). A temporary INI selected that exact MRA
and cleared the orientation path filter; the saved INI was unchanged. Preparation
included artwork checking and is separate from the measured core transition.

Baseline: the command FIFO had no reader for approximately 11 seconds. SAM had
already published `playing`; Main subsequently published `dstlk` approximately
0.9 seconds before opening the replacement FIFO. Monitor identified the selected
Darkstalkers MRA afterward. No human gameplay or audible confirmation is claimed.

Stop one second after dispatch reproduced premature audio cleanup. The old Menu
marker remained while the game loaded: volume bindings disappeared at 37.222 s,
`dstlk` appeared at 39.433 s, and the actual Menu return occurred at 42.123 s.
The full stop command returned after 13.98 seconds. This establishes early bind
removal, not audible output. The earlier old-Menu check was insufficient.

## Optional display process leak

Read-only syscall inspection found 41 orphan SAM Bash processes blocked in
`openat` on the exact `/tmp/.SAM_tmp/TTY_cmd_pipe` pathname with no OLED receiver.
Their parent was PID 1, and their terminal descriptors referred to deleted PTYs.
They were cleaned up only after rechecking each PID/start identity, parent and
blocked pathname. MCP and the live SAM owner were preserved. Two later old-code
writers were similarly cleaned before the next test.

The TTY helper now bounds FIFO writes and replaces background helper shells with
the timeout process. It clears inherited lifecycle traps and closes its copy of
the session-lock descriptor without unlocking the owner's shared lock. Seven
native tests passed in 4.860 seconds, covering absent receivers, quoted paths,
literal payloads, inherited traps, locks and the standalone OLED helper.

The proposed single-snapshot tree optimization is withheld: although much faster
on a sleeping tree, an active-fork test exposed surviving late-created children
with both old and proposed walkers. Its measurements do not describe the shipped
cleanup solution.

## Implemented cleanup and early Menu return

Preparation and delayed launch helpers now have registered private process groups.
The child waits at a STOP barrier until its PID/start, group and session identity
are captured. Cancellation freezes that leader, terminates its children, then
kills the verified private group, including late forks. It checks that no live
members remain. The callback receives `/dev/null` on stdin and does not inherit
the owner's transition lock. Unproven identities or uninterruptible I/O produce
a bounded failure, retain RAM evidence and block replacement admission.

The default Menu exit cancels those launch-capable jobs and runs critical
`session_stop`/`audio_stop` hooks before publishing an owner-tagged quiescence
marker. The stop controller can then request Menu while the existing owner
finishes mount, display and temporary-directory cleanup. No detached dispatcher
or resident cleanup daemon is added. Critical video configuration restoration
and unknown plugin stop hooks remain before this barrier. A live stopping owner
blocks the next session until housekeeping finishes.

The original Main/FIFO/marker generation is captured before termination and
carried into final confirmation, so an accepted early request does not force an
extra Menu reload. Audio restoration still requires owner exit and a fresh Menu
process holding the current command FIFO. The existing five-second owner-exit
deadline remains: visible Menu is not falsely reported as complete cleanup if an
old owner is still stuck. Keep-playing and M82 routing retain their separate
semantics.

OLED teardown now captures the exact session/pane/server identity and waits for
only its own bounded shutdown helpers. It removes the sleep marker only if that
marker's identity is unchanged. An absent OLED skips stale FIFO shutdown. Old
teardown helpers cannot remain detached after a normal owner return and reach a
later OLED session.

Live testing exposed a race in the first teardown revision: killing OLED in
parallel with its FIFO stop writer could remove the reader before delivery,
forcing a one-second timeout. The final revision gives the notification 200 ms
(plus 100 ms kill grace), reaps it, then stops the exact OLED session. Normal
game-info delivery retains its separate one-second limit.

MCP retains one default/Exit Menu request received while a verified ordinary
Next/Ignore command runs. It delivers that request only to the same owner.
Repeated Stop requests coalesce; this is not a general command-retry service.

## Measurements and validation

On matching isolated 21-process sleeping trees, old recursive cleanup took
7.07 seconds and private-group cleanup took 1.08 seconds; both had zero survivors.
The private-group active-fork fixture took 0.74 seconds with seven recorded
processes and zero survivors. These are cancellation fixtures, not physical
button-to-Menu measurements.

Three pre-installation default keyboard-action probes through MCP returned SNES
to Menu at 2.937, 3.451 and 2.155 seconds. Volume bindings disappeared at 3.039,
3.627 and 2.225 seconds. Input was injected through the existing remote-log test
route; physical controller latency and audible output were not measured.

The first complete installation returned Menu at 3.381, 3.201 and 3.157 seconds,
with total completion at 4.543, 4.518 and 4.186 seconds. That exposed the OLED
shutdown race above. With the correction installed, Menu appeared at 2.599,
3.218 and 2.809 seconds; completion was 3.453, 3.577 and 3.109 seconds. OLED was
running in these final samples but absent during the earlier baseline. These
small, differing workloads do not establish an overall responsiveness win over
the preceding release. Settled-game tracing still found 1.40 seconds in private
job cancellation; backend initialization and process scans remain costs.

A real test added two seconds to an optional display-exit hook. Menu appeared
at 2.937 seconds while the old owner remained in stopping until 4.831 seconds;
volume binds were removed at 5.363 seconds. This proves that Menu loading can
overlap owned cleanup without detaching it or permitting replacement admission.
Audio restoration still waits for that owner to exit as well as fresh Menu.

The guarded Darkstalkers mid-load probe kept volume binds until after the fresh
Menu FIFO appeared: fresh Menu/FIFO at 28.291 seconds, bind removal at 28.897,
command completion at 29.319. Total Stop duration was 11.87 seconds, dominated
by the in-progress core transition. This probe used the new freshness guard with
the old installed cleanup, before the complete candidate installation.

The final installed Darkstalkers test also passed: Stop during loading completed
in 14.19 seconds. The marker still said MENU during much of the CPS2 load, but
volume binds stayed present through the game and subsequent Menu transitions.
The final Menu FIFO was observed at 31.888 seconds and binds disappeared at
32.590 seconds. This confirms ordering, not faster core loading or a command
acknowledgement. Retry writes can still cause an extra Menu transition.

The first full native run passed 413 of 416 tests. Three core-policy fixtures
accidentally queried the real tmux SAM session instead of an isolated stub;
their isolation was corrected. All 77 final focused tests then passed, covering
private jobs, early Menu, freshness, OLED shutdown and core policy. The final
full suite passed all 430 tests in 372.244 seconds. A subsequent narrowly scoped
fix retained processes whose zombie main thread still has other threads: all
104 affected cleanup, shell, session and normal-loop tests passed in 190.640
seconds, including two new deterministic regressions. Blocked I/O was simulated;
no physical storage fault was induced.

The final OLED correction passed all 13 native OLED tests in 7.452 seconds,
including a real private FIFO and the missing-reader shutdown deadline. The
430-test suite predates the final thread and OLED corrections; the affected
104-test and 13-test runs validate those subsequent changes. No blocked SAM
FIFO writers remained in the final check; two legacy instrumentation shells
were removed only after verifying exact PID/start, parent and blocked pathname.

MCP Menu detection was audited and deliberately left unchanged after user
clarification. Current code reads Main's `/tmp/CORENAME`; it does not require a
`menu.rbf` command-line argument or a preceding SAM Menu return. Its existing
phase/launch arming and two-second external-Menu debounce remain. The stronger
Main/FIFO freshness checks described here belong to stop/audio completion.

Live installed-runtime checks passed SNES launch and Monitor artwork, conditional
start preserving the owner, pause/resume, Next/Previous, Menu return and volume
bind ordering, and keep-playing with `game_kept=yes`. Stops immediately following
fresh launches took 5.07 and 5.51 seconds; these include in-progress transitions
and are not comparable to the settled-game default-input samples above.

Read-only initialization profiling found 327–373 ms for full definitions/config
versus 170–184 ms for a reduced set, excluding directory/module initialization.
The reduced backend was not implemented: external display and custom plugin
hooks must remain intact. No claimed timing improvement relies on skipping them.

## Install and rollback

The source archive includes the complete runtime. Large optional binaries are
excluded and existing copies are retained. Transfer `sam-response-candidate.tar.gz`
to `/tmp` on the MiSTer, then run:

```sh
tar -xzf /tmp/sam-response-candidate.tar.gz -C /tmp
python3 /tmp/sam-response/MiSTer_SAM_install.py --source-dir /tmp/sam-response --mister-root /media/fat --branch test
bash /media/fat/Scripts/MiSTer_SAM_on.sh start
```

The installer backs up only `MiSTer_SAM.ini`; ROMs, artwork, user configuration,
maps, plugins and Ignore lists are preserved. It compares files before writing
and replaces changed files atomically. The release as a whole is not atomic.

To restore the preceding lean runtime, transfer the retained
`sam-lean-runtime-candidate.tar.gz` from the earlier deliverable to `/tmp`:

```sh
tar -xzf /tmp/sam-lean-runtime-candidate.tar.gz -C /tmp
python3 /tmp/sam-lean-runtime/MiSTer_SAM_install.py --source-dir /tmp/sam-lean-runtime --mister-root /media/fat --branch test
bash /media/fat/Scripts/MiSTer_SAM_on.sh start
```

`sam-response.patch` applies to that preceding lean archive;
`sam-complete-from-fff2ebf.patch` includes the entire accumulated refactor against
repository HEAD `fff2ebfa156d5ba7b158752632624314205292c5`. Both patches were
apply-checked; applying the incremental patch reproduced all candidate files.
Git publication is separate from installation.

Installed on the real MiSTer with all 132 runtime files matching the final
candidate and no retired Python timer controllers running. The final INI-only
backup is `/media/fat/Scripts/.SAM_refactor_backups/install-20261009-221852-o7xqdw2j/MiSTer_SAM.ini`.
