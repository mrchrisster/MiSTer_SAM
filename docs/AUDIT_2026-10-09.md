# SAM embedded runtime audit — 2026-10-09

Baseline: test branch commit `fff2ebf`. The patch uses Bash 5 and Python 3.9
standard-library features already present on this MiSTer. No new INI options,
resident daemons, input grabs, or polling-rate settings were added.

## Findings and implemented changes

1. **Mute restored before Menu.** The owner EXIT trap removed volume binds before
   MCP sent the Menu command. Menu exits now publish an owner-tagged RAM marker
   before stopping SAM, retain audio through cleanup, confirm `CORENAME=MENU`,
   then restore volume. Failed Menu loads stay muted and report failure. CLI
   retries and MCP reject replacement owners. MCP checks Menu every 100 ms
   instead of always waiting a full second before the first confirmation.
2. **Startup cancellation used a different stop path.** Buffered ordinary input
   now cancels and joins the launcher before applying the same verified Menu
   exit. Next still coalesces; Start/Zaparoo preserves an already playing game.
3. **BGM Keep playing could reload an old console.** The global MGL fallback could
   belong to a previous game, while owner cleanup deleted the current record.
   SAM records the actual launch path in its RAM session and captures it before
   cleanup. Internal Monitor Play also cancels preparation and delayed BIOS
   actions before reload. Failed handoffs return an error acknowledgement.
4. **Joystick snapshots were limited to 64 records.** Axes precede buttons, so
   larger adapters could lose later buttons. One raw read now uses discovered
   button+axis counts, with a bounded fallback. The existing 20 ms repeated-open
   method is retained for MiSTer's grabbed devices. Keyed INIT comparison avoids
   queued-event/record-order mismatches and scans only changed controls.
5. **Input output could block dispatch.** Activity printing ran before dispatch
   and while holding the state lock. Diagnostics use the existing bounded debug
   queue after releasing that lock.
6. **Silent HID/mouse readers could survive cancellation.** Nonblocking reads and
   readiness waits now close their descriptors within 250 ms when idle. The
   existing debounce is interruptible. No persistent evdev event-reader change
   is made.
7. **Scan/filter errors looked like empty collections.** Builders and filters
   now distinguish a valid empty list from I/O, matcher and metadata errors.
   Background failures are reported rather than retried indefinitely. Partial
   failed scans cannot replace a working public list; failed filters cannot
   acquire a successful cache stamp. AWK input errors no longer loop on -1.
8. **Unchanged catalogues caused SD writes and re-filtering.** Publication compares
   content first, preserving timestamps for identical lists. MRA indexing uses
   one traversal, and runtime avoids sorting generic results twice. Cache stamps
   describe the inputs actually filtered so changes during filtering are seen
   on the next preparation.
9. **Updates rewrote the whole payload; failed copies could truncate files.**
   Identical files are skipped using buffered comparison. Changed payload files
   are staged in the target directory before replacement. Only the INI is backed
   up. Unchanged INI/release-channel records are not rewritten. This is per-file
   atomic publication, not a transactional release-wide or power-loss guarantee.
10. **Asset download failures could publish partial data or report success.**
    Downloads stage their output, retain working files on failure, preserve
    executable mode, and propagate bootstrap errors. Metadata HEAD requests are
    bounded. Existing legacy TLS settings and size-based asset update policy
    were not redesigned in this audit.
11. **BGM process matching was too broad.** Exact executable/script matching
    replaces ps/grep substring kills. The installed `bgm.sh` is an ARM ELF binary,
    so it is explicitly supported alongside interpreted versions. Healthy BGM
    avoids fixed startup sleeps; socket operations are bounded. Bundled Python
    cleanup reaps only its owned media/watcher children. Those bundled changes
    do not modify the separately installed native BGM binary.
12. **Menu cancellation and confusing options.** The main screen has eight
    entries, prioritizing Start, Stop, Next, Keep playing and Exclude. Video
    cancellation preserves settings; timer input is validated; core arrays and
    whitespace in edited values survive; all-Arcade clears both orientation
    filters. BGM prerequisites complete before changing settings, and disabling
    SAM BGM preserves its external installation. Controller help explains
    MiSTer's global mapping rather than writing unused legacy SAM JSON.
13. **One failed teardown callback skipped later modules.** Resource-release
    hooks now attempt every callback, retaining the first error. Policy hooks
    still fail fast. Module docs describe the code map, ownership, core rules,
    preparation boundaries and teardown contract.
14. **Per-core BGM switches flushed all filesystems.** Removed a global sync after
    unmounting the temporary volume bind; the unmount is immediately visible
    without flushing unrelated SD/USB writes.

## Automated validation

Native device: `armv7l`, Linux `6.18.38-MiSTer`, Bash `5.0.18`, Python `3.9.6`.
Fixtures run from `/tmp/sam-audit-current`, with private configuration, lists and
state; hardware commands are mocked. This is native software validation, not
visual proof that every game core or optional mode works.

**304 tests passed in 224.999 seconds on the real MiSTer.**
All 39 shell files also passed Bash syntax checks. Python source compilation
passed. The final input-only rerun passed **61 tests in 7.272 seconds**, covering the
last startup-log queue adjustment. Counts overlap and must not be added.

The suite covers ownership/PID reuse, launch cancellation, Next/Previous,
pause/resume, ignore/exclusions, control HTTP acknowledgements, timers, filters,
empty catalogues, archive and multi-root indexing, MGL generation, core policies,
M82/video constraints, commercial picking, artwork/status contracts, installer
preservation/failures, menu cancellation, and input mapping/hotplug/reader cleanup.
Mode fixtures do not prove full M82 BIOS, commercial video, tty2oled or external
BGM hardware playback. No new physical controller or audible confirmation was
available. No full ROM hashing, ROM collection edits or live candidate install
was used for these tests.

Native observation-only measurements:

| Measurement | Result | Scope |
| --- | --- | --- |
| Pipe-ready to reader callback, 30 samples | median 0.363 ms; max 1.132 ms | Kernel pipe fixture, not a physical key |
| Silent-reader cancellation, 5 samples | max 249.810 ms | Existing 250 ms cancellation bound |
| Descriptor growth across reader probe | 0 | Probe process only |
| Patched isolated js0 reader | 6.41%, 6.56% of one CPU | Two five-second samples |
| Baseline isolated js0 reader | 7.46%, 6.56% of one CPU | Same live device, reverse-order samples |

CPU samples overlap and include reader setup; they do not establish a statistically
significant improvement or whole-SAM CPU usage. Each observer stopped cleanly,
with zero descriptor growth and no dispatched game controls. Joystick polling
remains 20 ms. Real button-to-Menu latency also includes main-loop scheduling,
owned-job shutdown and FPGA core loading.

## Install and rollback

Use the complete candidate archive, not just the top-level launcher. Extract it
to a temporary directory on the MiSTer, then run the included installer:

```sh
tar -xzf /tmp/sam-audit-candidate.tar.gz -C /tmp
python3 /tmp/sam-audit-current/MiSTer_SAM_install.py \
  --source-dir /tmp/sam-audit-current --mister-root /media/fat --branch test
```

This updates `.MiSTer_SAM` plus its entry/installer scripts, preserves custom
configuration/maps/plug-ins/Ignore lists, backs up only `MiSTer_SAM.ini`, stops
SAM/MCP for installation, and restarts MCP if it was running. It does not replace
`/media/fat/Scripts/bgm.sh`, which is owned by the separate BGM installation.

The unified diff is against `fff2ebf`. In a checkout at that base:

```sh
git apply --check sam-audit.patch
git apply sam-audit.patch
```

Rollback scripts by extracting the supplied baseline archive to `/tmp` and
running its installer with that extracted source:

```sh
tar -xzf /tmp/sam-audit-baseline.tar.gz -C /tmp
python3 /tmp/sam-audit-baseline/MiSTer_SAM_install.py \
  --source-dir /tmp/sam-audit-baseline --mister-root /media/fat --branch test
```

Restore a chosen saved INI
only if you also want to undo configuration changes. Do not restore whole SD
or ROM directories. The baseline commit is also available at:
https://github.com/mrchrisster/MiSTer_SAM/tree/fff2ebf

## Remaining verification limits

- An automated test cannot hear the brief unmute burst or operate arbitrary
  physical controllers. The fixed command order has automated coverage; HDMI/
  audio capture or a user check is still needed to confirm the symptom on hardware.
- The separate installed native BGM binary was identified, not patched or fully
  exercised. Its internal cleanup is version-dependent.
- Existing strict duplicate-name normalization and optional asset TLS/update
  policy remain separate concerns; this audit does not claim every legacy
  function or every supported core has been exhaustively tested.
- File-by-file update publication is recoverable via reinstall, not a multi-file
  transaction. A forced power loss during an update still requires recovery.
