# Coordinator migration, first stage — 2026-10-09

This candidate includes the preceding audit fixes plus the first architectural
migration stage. It has not been installed into the live MiSTer or pushed to
GitHub. The running installation and ROM collection remain separate from the
test candidate.

## Implemented

- Shared local command gateway for CLI, menu and MCP actions. MCP invokes it in
  process; commands do not start another resident service.
- Extracted Python lifecycle coordinator and immutable verified owner snapshots.
  Input readers, mapping precedence and polling frequency are retained.
- Shared Bash session admission, phase publication and cleanup for normal,
  M82 and video loops. Concurrent starts cannot acquire the same runtime.
- Owner-bound input dispatch to exact panes; guarded teardown also accounts for
  tmux server restart and reuse of session IDs.
- One Menu/audio exit implementation, checked every 100 ms, with stale-owner
  rejection before final resource changes.
- Stale worker record rejection, signal-safe transition cleanup and explicit
  propagation of rejected video launches.
- External teardown explicitly releases inherited lock descriptors so background
  tty2oled cleanup cannot delay a new session. Hot phase transitions retain one
  lock helper and builtin unlock.
- Removed a preset's broad shared temporary-directory reset. The next session
  already has private lists and filter-cache input stamps.
- Required coordinator files/imports are validated before installation changes.
  Existing config-only backups and write avoidance remain in place.

See [ARCHITECTURE.md](ARCHITECTURE.md) for responsibilities, command flow, module
extension points and the remaining migration. The game engine, special-mode
timers and launch adapters are still Bash; a full Python engine and release-wide
atomic update switching are not included in this stage.

## Validation

Native platform: ARMv7l MiSTer, Bash 5.0.18, Python 3.9.6, tmux 3.1c; the installed
flock supports bounded acquisition. All test files/configuration are private
temporary fixtures. MiSTer launch/audio operations are mocked. The real tmux
tests create and remove only UUID-named private servers.

Full-suite result: **355 tests passed in 188.364 seconds** on the MiSTer.
This includes the two real private-server tmux integration tests and installer
preflight/import/syntax validation. Log: `native-full-tests.log`.

After that run, external exit finalization gained an explicit unlock for
descriptors inherited by background teardown helpers. Focused session, shell
lifecycle and Monitor-control regressions then passed: **78 tests in 66.799
seconds**, including the new inherited-descriptor case. Log:
`native-final-lock-tests.log`. The final tree therefore contains 356 tests;
the 355-test full run preceded that last added regression, and the final change
was validated by the 78-test focused run rather than another complete rerun.

Host checks: all 53 Python files parsed successfully. Both supplied patches
passed `git apply --check` against their documented base trees; Windows emitted
expected executable-bit warnings for the complete patch.

The initial integration passes caught old fixtures bypassing session admission
and mocking timeout calls as hardware reloads; these fixtures now use the shared
lifecycle or explicitly isolate the intended boundary. A prepared-Next timing
failure also prompted reducing lock acquisition/unlock from three helper
processes to one. Its timing fixture waits for an actual prepared candidate,
rather than assuming that control readiness means preparation has finished.
Both focused engine tests then passed on the MiSTer.

The device continued running its existing SAM and changing cores during tests,
so CPU availability was variable. These tests do not establish physical
button-to-Menu latency or prove audible behavior. Full visual ROM/mode playback
with this candidate remains unverified.

## Install

Copy `sam-coordinator-candidate.tar.gz` to `/tmp` on the MiSTer, then:

```sh
tar -xzf /tmp/sam-coordinator-candidate.tar.gz -C /tmp
python3 /tmp/sam-architecture-current/MiSTer_SAM_install.py \
  --source-dir /tmp/sam-architecture-current --mister-root /media/fat --branch test
```

Install the complete candidate, including the new `sam/` package and
`lib/session.sh`. Copying only the launcher is insufficient. The installer backs
up only `MiSTer_SAM.ini`, preserves custom maps/plugins/Ignore lists, and restarts
MCP if it was running. No additional INI configuration is required.

`coordinator-only.patch` applies to the preceding `sam-audit-candidate` tree;
`sam-complete-from-fff2ebf.patch` applies to Git commit `fff2ebf` and includes both
the audit and coordinator changes. Check a patch against its matching base:

```sh
git apply --check sam-complete-from-fff2ebf.patch
git apply sam-complete-from-fff2ebf.patch
```

## Rollback

Use the supplied `sam-audit-baseline.tar.gz`, containing commit `fff2ebf`:

```sh
tar -xzf /tmp/sam-audit-baseline.tar.gz -C /tmp
python3 /tmp/sam-audit-baseline/MiSTer_SAM_install.py \
  --source-dir /tmp/sam-audit-baseline --mister-root /media/fat --branch test
```

The older runtime does not import the new package, so unused new files can remain
without affecting rollback. Restore a saved INI only to undo configuration
changes. No full installation or ROM backup is created or required by these
commands.
