# Normal-session coordinator migration — 2026-10-09

Historical report: this Python timer/bridge experiment was superseded by
`LEAN_RUNTIME_2026-10-09.md` after measured resource regression. Its package and
test results describe that intermediate build, not the current runtime.

## Implemented scope

Normal and roulette sessions now use a persistent Python controller for
Select/Prepare/Launch/Play/Advance decisions and monotonic timing. The Bash
foreground process remains the verified hardware owner. Existing catalogue,
artwork, launch and commit adapters remain in place. The old unused normal-loop
copy was removed; M82/video compatibility loops remain separate.

Changes:

- `sam/engine.py`: explicit preparing/loading/playing/paused/stopping states,
  monotonic pause/resume, indefinite zero timer, loading-Next coalescing, Previous
  replay, and preparation scheduling at most once per second.
- `sam/game.py`: immutable candidate with bounded literal parsing; rejects
  malformed/duplicate identity or location fields before launch. Carries the
  exact existing location rather than reconstructing FAT/USB or archive paths.
- `lib/coordinator.sh`: persistent anonymous-pipe adapter; no per-tick Python
  subprocess or timer-state file writes. Bash performs final validation, hardware
  launch and history commit. Monitor pause/resume is acknowledged after the
  authoritative controller update.
- Controller loss terminates the owned loop with an error and cleanup. A
  PID/start watchdog also exits the controller if its Bash owner disappears,
  even if another descendant inherited a pipe. Preparation/launch workers close
  those descriptors and remain cancellable through existing ownership checks.
- Automatic MCP starts now check idle state under shared serialized admission.
  They preserve a live owner or a starting SAM pane, closing the manual-start
  race observed during live smoke checks. Explicit manual starts retain their
  replacement behavior; no extra user option is introduced.
- Start admission waits briefly for ownership publication before unlocking;
  daemon children close inherited lock descriptors. An unverified occupied pane
  produces a clear error instead of a duplicate spawn. MCP observes owner exit
  and resets the idle interval once, preventing immediate restart after CLI stop.
- Installer preflight requires/imports the new controller files before modifying
  the installation. Only the INI is backed up; ROMs and custom lists are intact.

This is the normal/roulette step of the staged migration. M82 needs a foreground
sequence adapter preserving BIOS behavior and play extensions. Video needs
explicit playback ready/failure events and foreground authorization for worker
hardware actions. Neither is claimed as migrated here. Their existing behavior
is preserved and covered by regression fixtures. The duration-policy interface
is an internal extension point, not a complete dynamic Python plugin system.

## Validation

Native ARMv7l MiSTer with Python 3.9.6 and Bash 5.0.18:

- Full regression: 387 tests passed in 246.882 seconds before the final deadline
  and start-admission refinements.
- Final timer/controller subset: 28 tests passed in 86.093 seconds, including
  pause/resume at expiry and owner-loss cleanup.
- Start/input/cleanup subset after the admission and idle reset changes: 106
  tests passed in 64.437 seconds.
- After the final inherited-lock-descriptor adjustment: all 60 shell tests
  passed in 42.093 seconds. These subsets overlap; counts are not additive.

Isolated fixtures mock hardware launch/audio operations and use private files.
They exercise candidate rejection, zero/finite timers, pause beyond the original
deadline, Next/Previous, loading bursts, controller death and stop during blocked
preparation. Existing fixtures also cover artwork filtering, special-mode
selection, installer behavior, input mappings and private tmux commands.

Live validation uses actual ROMs and Monitor HTTP state/artwork responses.
Software evidence cannot establish visual gameplay, correct audible transitions
or physical controller latency without a person observing the display/input.

Final live run passed: actual SNES ZIP-member launch with a 96,137-byte image
response from Monitor; automatic-start preservation of the current owner;
pause/resume; Next and Previous returning to the original ROM; keep-playing with
`active=no` and `game_kept=yes`; and two Menu stops. At 20 ms sampling, volume
bindings remained until Menu was observed, and were released afterward (152 and
213 samples). Whole stop commands took 4.163 and 5.632 seconds; this is not a
physical input latency measurement. No immediate automatic restart occurred
during the two-second post-stop checks. Configured automatic selection was then
restored and launched a TGFX16-CD CHD from `/media/usb0`.

Earlier live attempts exposed the two admission races described above; their
failure logs informed the fixes. The final scripted run completed successfully.
M82/video were tested with regression fixtures, not actual playback in this run.

Short isolated eight-second resource samples measured the prior Bash owner at
3,436 KiB RSS and 2.12% of one CPU. The new Bash owner plus Python controller
used 11,584 KiB RSS and 4.87% combined CPU (controller RSS 8,232 KiB). This is a
reliability/structure migration with a measurable resource cost, not a demonstrated
speed improvement. Background device activity and short samples limit comparison.
Timing and bridge traffic stay in memory; no countdown file is written per tick.
